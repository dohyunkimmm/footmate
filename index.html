WHY THIS PROJECT
CORE SERVICE

예약보다 중요한 것은 “누구와 경기하는가”였습니다

기존 풋살 서비스는 예약과 모집에는 강했지만, 실력에 맞는 팀 구성, 노쇼 대응, 다시 참여할 이유까지는 충분히 제공하지 못한다고 판단했습니다.

PROBLEM

풋살 매칭은 아직 “운”에 가깝다

01

실력 차이

오픈채팅 기반 모집은 팀원 간 실력 편차가 커 경기 만족도가 낮아집니다.

02

노쇼 리스크

경기 직전 불참이 발생하면 팀 구성과 경기 품질이 저하됩니다.

03

관계 지속성 부족

경기 후 관계와 기록이 이어지지 않아 다시 함께할 팀원과 성장 기록이 쌓이지 않습니다.

문제 → ELO 기반 매칭 + 참가비 결제·보증금 예치 + 경기 후 평가·성장 기록

STRATEGY & DESIGN PRINCIPLES

Fair Match · Trust · Growth

기능을 나열하지 않고, 사용자가 다시 참여하고 싶은 경기 경험을 만드는 세 가지 원칙으로 설계했습니다.

01 · FAIR MATCH

Personalized Matching

ELO·플레이 성향·위치를 조합해 실력이 비슷한 팀을 추천합니다.

02 · TRUST

Reliable Operation

참가비 결제와 보증금 예치, 체크인으로 노쇼 리스크와 운영 불안을 낮춥니다.

03 · GROWTH

Reason to Return

경기 결과·평가·ELO 기록을 다음 경기 추천과 재참여로 연결합니다.

MOSCOW

기능 우선순위

Must

Should

풋살장 예약 연동 · 팀원 즐겨찾기 · 상세 필터 · 관리자 정산 대시보드

MATCHING LOGIC · INITIAL HYPOTHESIS

입력부터 경기 결과까지 이어지는 동적 ELO 구조

5개 온보딩 응답으로 초기값을 만들고, 실력·성향·위치 적합도를 계산한 뒤 경기 결과로 ELO를 갱신합니다.

50%

ELO

50% ELO 실력 자가 실력·경기 빈도로 초기값을 산정하고 상대 ELO와 승·무·패로 업데이트
30% 플레이 성향 포지션·선호 시간대·경기 빈도의 조건 적합도를 반영
20% 위치 편의성 선호 활동 지역과 구장 권역의 일치도를 기준으로 추천

경기 후 ELO = 현재 ELO + K(32) × (실제 결과 − 기대 결과) · 팀원 평가는 ELO가 아닌 별도 매너 기록으로 저장합니다. ※ 가중치와 초기값은 사용자 테스트가 필요한 규칙 기반 가설입니다.

AI AGENT WORKFLOW
SYSTEM PM BLUEPRINT

추천 결과를 보여주는 데서 그치지 않고, 다음 행동까지 설계하는 에이전트

사용자의 목표와 현재 상태를 파악하고 필요한 데이터를 조회한 뒤, 설명 가능한 추천과 복구 행동을 제안하는 5단계 AI Agent Workflow를 설계했습니다.

01 · CONTEXT

목표·상태 수집

포지션·빈도·실력·지역·시간과 정원·결제·체크인 상태를 수집합니다.

02 · PLAN

과업 계획

일반 추천인지, 만석·노쇼·결제 실패 같은 복구 과업인지 분류합니다.

03 · TOOLS

도구 실행

프로필·경기 목록·ELO 계산기·운영 정책을 조회해 후보와 근거를 만듭니다.

04 · GUARDRAIL

품질·HITL

누락·최신성·정원 충돌을 확인하고 결제·참가·신고 전 사용자 승인을 받습니다.

05 · OBSERVE

행동·로그

추천·대기·대체 행동을 제안하고 상태 전환과 퍼널 이벤트를 기록합니다.

현재 확인 가능규칙 기반 추천 계산 · 추천 이유 · 대기·대체 참가 · 예외 복구 · 브라우저 내부 이벤트 로그
향후 실제 연동LLM·DB·결제·알림·운영자 도구 · 자동 실행은 가드레일과 사용자 승인 이후에만 허용
SERVICE DATA & QUALITY
DATA CONTRACT · OWNERSHIP

추천 품질을 화면이 아니라 데이터 계약으로 관리합니다

핵심 엔터티와 검증 규칙, 실패 시 처리와 소유자를 연결해 데이터 품질 기준이 서비스의 다음 행동을 결정하도록 설계했습니다.
