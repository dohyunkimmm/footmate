# FootMate Case Study 5.2 · 페이지 구성 검토

기준 소스: `b20efca837842d9719ddbdbf7695799488e52641`의 Case Study 5.1.1.
수정 범위: 공개 Case Study의 제목·설명·키워드, 페이지 구성, 카드 위계, 여백과 제품 화면 표현.

## 공통 기준

- 각 페이지는 하나의 제목, 한 문장의 설명, 세 개의 핵심 키워드로 시작합니다.
- 요약의 정보는 보존하고, 반복 카드 대신 얇은 구분선과 같은 기준선으로 정리합니다.
- 카드 제목과 설명의 간격, 설명 행간, 보조 캡션을 공통 규칙으로 관리합니다.
- 데스크톱의 좌우 여백은 화면 폭에 따라 조절하고, 모바일은 20px, 360px 이하에서는 16px의 같은 경계를 사용합니다.
- 모바일은 불필요한 화면 높이 채우기를 없애고 내용에 맞춰 페이지 길이를 정합니다.
- 낮은 데스크톱 화면은 글자를 줄여 끼워 넣지 않고 페이지 안에서 세로 스크롤을 허용합니다.
- 제품의 주요 근거 화면은 기존 원본을 유지하고, 강제 높이·잘라내기를 해제해 전체 비율을 보존합니다.
- AI 실제 연결, 추천 로직의 책임, 인증·참가 경계, 사용성 검증과 성과 지표의 구분은 유지합니다.

## 검증 범위와 한계

로컬 검증: 1440×1000, 1280×720, 390×844, 320×740의 13개 페이지, 총 52개 상태에서 제목·키워드·가로 넘침·페이지 탐색과 JavaScript 실행 오류를 확인했습니다. 기존 제품 PNG 원본 6개를 기준 커밋에서 가져와 최종 화면과 관련 회귀 검사 40개를 검증했습니다. 생성 번들의 재현성과 캐시 버전 동기화도 통과했습니다.

제품 화면은 새로 촬영한 현재 앱 화면이 아니라, 기존에 사용 중이던 시각 기준입니다. 추천 화면은 1440×900, 상세와 경기 당일 화면은 390×844의 원본을 유지합니다. 가로 화면과 세로 화면은 서로 다른 크기 규칙을 적용하고 강제 크롭을 제거했습니다. 표지는 기존 HTML 프리뷰입니다. 전체 저장소 CI와 배포 후 검증은 이 로컬 검증과 구분합니다.

로컬 검증은 배포 후 최종 확인을 대신하지 않습니다.
