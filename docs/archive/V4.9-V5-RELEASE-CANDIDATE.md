# FootMate v4.9 — v5 Release Candidate

v4.9는 v4.8 Platform Architecture를 사용자 경험 회귀 기준으로 두고 v5 전환 전에 바뀌면 안 되는 제품·관측·연동 계약을 고정하는 Release Candidate다.

## Frozen IA

`welcome → setup → home → discover → detail → auth → checkout → success → schedule → profile`

사용자 핵심 여정은 `Find → Decide → Join → Play → Return → Personalize`를 유지한다. Real / Guided / Evidence mode와 16-section Case Study 구조도 유지한다.

## Design system contract

`src/v4/release-candidate.css`가 기존 v4 visual token을 semantic alias로 묶고 최소 44px control, reduced-motion 기준을 공통 계약으로 고정한다. 기존 feature CSS는 compatibility surface로 남기며 v5에서 검증 없이 시각 동작을 다시 만들지 않는다.

## Observability contract

stable local event names:

- `recommendation.selected`
- `join.started`
- `join.completed`
- `checkin.completed`
- `postgame.submitted`

Event schema는 v1을 유지하고 `footmate:v4:events` local log에만 기록한다. external analytics delivery는 연결하지 않는다.

## Provider mock contract

v5 연결 후보 provider는 `auth`, `payment`, `capacity`, `notification` 네 경계로 고정한다. v4.9의 provider는 모두 deterministic mock이며 외부 네트워크 side effect가 없다. 실제 OAuth, member DB, PG, realtime capacity, notification backend가 연결됐다고 표현하지 않는다.

## Migration / rollback rehearsal

Session schema는 v2를 유지한다. RC contract는 migration 전 snapshot checkpoint를 만들고 기존 migration을 실행한 뒤 원본 snapshot으로 rollback 가능한지 deterministic test로 검증한다. v4.9 자체는 새로운 session schema migration을 추가하지 않는다.

## Performance / accessibility budget

- app HTML ≤ 16 KB
- first-party CSS ≤ 180 KB
- first-party JS ≤ 320 KB
- first-party CSS/JS requests ≤ 24
- responsive widths: 320 / 375 / 390 / 430px
- welcome → setup → home → detail → auth → checkout full-flow serious/critical axe violations: 0

## v5 promotion rule

v5.0에서 실제 provider가 연결되면 mock contract를 대체하되 동일 interface와 recovery semantics를 유지한다. 실제 연동하지 않은 provider와 AI inference는 simulation/mock 경계를 그대로 공개한다. v4.9의 Production 승격 여부는 PR QA, exact Vercel Production HTTP/Chromium, Render exact SHA 검증 후 durable release 문서에 기록한다.
