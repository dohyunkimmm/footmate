# FootMate v5.0 — Connected Matchday Platform

> Historical archive — 이 문서는 v5.0 출시 당시 architecture/provider boundary를 보존하는 기록입니다. 현재 제품·QA·연동 상태의 Source of Truth는 root `README.md`와 `docs/RELEASE-HISTORY.md`입니다.

## Goal

v4.9에서 고정한 IA·design system·observability·provider contract를 유지하면서 Matchday Companion을 실제 서비스 연동을 수용할 수 있는 제품 아키텍처로 전환합니다.

## Runtime architecture

- Compatibility runtime: existing v4.9 product UX and session schema v2
- v5 domain boundary: recommendation / participation / matchday / return
- Cross-domain guardrail: selected match → successful participation → matchday check-in → return feedback 식별자와 상태 일관성 검증
- Provider registry: auth / payment / capacity / notification provider를 동일 interface로 주입
- Presentation disclosure: runtime에서 v5 version, connection mode, provider catalog, domain ownership을 명시적으로 노출

## Provider boundary

v5.0 Production의 기본 provider는 모두 deterministic mock입니다. OAuth, member DB, 실제 payment gateway, realtime capacity, notification backend, external AI inference를 실제 연결한 것으로 표현하지 않습니다.

Provider가 `external: true`를 선언하려면 `connected: true`와 v4.9에서 고정한 method contract를 함께 만족해야 합니다. 실제로 연결·검증된 provider만 `connected` 및 Production capability로 승격할 수 있습니다.

## State consistency

- recommendation의 selected match와 participation match가 다르면 invalid
- successful participation은 match identity가 있어야 함
- participation과 matchday의 match identity가 달라지면 invalid
- successful participation 없이 checked-in 상태로 갈 수 없음
- matchday와 return의 match identity가 달라지면 invalid
- check-in 없이 completed Return 상태로 갈 수 없음

이 검증은 기존 v4.9 UX를 대체하지 않고 domain/application boundary에서 잘못된 cross-domain 상태를 탐지하는 guardrail입니다.

## Non-goals / current limits

- 신규 OAuth 또는 member DB 연동
- 실제 PG 결제
- realtime capacity/participant backend
- 실제 notification delivery
- external analytics delivery
- external AI/ML inference
