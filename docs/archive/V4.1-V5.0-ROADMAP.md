# FootMate v4.1 → v5.0 Product Evolution Roadmap

> Historical archive — 이 문서는 v4.1~v5.0 단계별 진화 계획을 보존하기 위한 기록입니다. 현재 제품·QA·배포 상태의 Source of Truth는 root `README.md`와 `docs/RELEASE-HISTORY.md`입니다.

이 문서는 v4.0.1을 회귀 기준으로 두고 FootMate를 단계적으로 고도화하기 위한 실행 로드맵입니다. 각 단계는 독립적으로 QA·Production 검증을 통과한 뒤 다음 단계로 이동합니다.

## Release discipline

- Stable regression baseline at roadmap start: v4.0.1
- Protected main flow: branch → PR → GitHub Actions QA → merge → exact Vercel Production verification → Render verification → durable docs sync
- PR QA는 GitHub Actions 우선. 실제 시각 QA가 필요한 경우에만 Preview를 사용합니다.
- 외부 AI, 회원 DB, OAuth, 실제 PG, 실시간 정원·알림 backend는 실제 연동 전까지 명확히 prototype boundary로 표시합니다.
- 각 minor release는 사용자 가치 하나를 끝까지 연결하며, 미완료 기능을 다음 버전의 완료 항목처럼 표현하지 않습니다.

## v4.1 — Recommendation Core

**목표:** 설정한 지역·포지션·레벨이 실제 추천 순위와 추천 이유를 바꾸게 합니다.

- preference-aware ranking
- 지역·체감 레벨·선호 포지션·이동 시간 기반 설명 가능한 적합도
- 숫자 점수는 내부 정렬에 사용하고 사용자 화면은 이유 우선
- 지역별 sample match coverage 확대
- Home / Discover / Detail의 동일 추천 계약
- preference change → ranking change E2E gate

**완료 기준:** 서로 다른 preference 조합에서 추천 1순위와 이유가 실제로 달라지고, 선택 경기 continuity·기존 참가 흐름 회귀가 없어야 합니다.

## v4.2 — Discovery & Search

**목표:** 추천을 받은 뒤 사용자가 스스로 탐색 범위를 조절할 수 있게 합니다.

- 날짜·시간·거리·가격·포지션 필터
- 적합도 / 거리 / 마감 임박 정렬
- active filter summary + clear all
- zero-result recovery와 조건 확장 제안
- 검색 상태 URL/session persistence
- mobile filter sheet + keyboard accessibility

## v4.3 — Decision Detail

**목표:** 경기 상세를 실제 참가 판단 화면으로 고도화합니다.

- recommendation reason breakdown
- 참가자 구성·포지션 균형
- 시설·운영 규칙·준비물
- 취소/환불 정책 시각화
- 남은 자리 urgency의 과장 없는 표현
- detail compare / save intent 상태 설계

## v4.4 — Join & Payment State Machine

**목표:** 참가 의도부터 확정까지의 상태를 명확한 계약으로 만듭니다.

- auth → checkout → confirmation 상태 모델 분리
- pending / success / failure / retry / cancel recovery
- 결제 수단 선택 simulation
- duplicate submit 방지
- selected match / price / policy snapshot consistency
- reload-safe participation state

## v4.5 — Matchday Operations

**목표:** 참가 이후 실제 경기 당일에 필요한 행동을 제품 중심으로 만듭니다.

- upcoming → matchday → checked-in 상태
- check-in window / arrival status
- route / venue instructions
- late / cancellation / match update recovery
- 팀 공지·메시지 UX contract
- 경기 시작 전 actionable home

## v4.6 — Return Loop & Reputation

**목표:** 경기 후 데이터가 다음 참가 경험으로 돌아오게 합니다.

- postgame rating flow
- attendance / completion history
- 체감 난이도 feedback
- 다음 추천에 feedback 반영
- player reliability / sportsmanship 표현 원칙
- history / repeat match discovery

## v4.7 — Personalization & Memory

**목표:** 반복 이용자에게 설정을 다시 묻지 않고 더 빠른 결정을 제공합니다.

- saved preference profile
- recent behavior signals
- favorite areas / time windows / formats
- recommendation reason personalization
- explanation controls: “왜 추천됐나요?”
- reset / edit / privacy boundaries

## v4.8 — Platform Architecture

**목표:** prototype UI와 domain logic을 분리해 실제 연동 가능한 구조로 만듭니다.

- domain / application / presentation layer separation
- typed-like schema contracts in plain JS or selected runtime architecture
- explicit session schema version + migration
- repository / provider interfaces
- event model for recommendation, join, check-in, postgame
- deterministic fixtures and contract tests

## v4.9 — v5 Release Candidate

**목표:** v5 전환 전 IA·design system·observability·integration contract를 고정합니다.

- final IA review
- design token / component consolidation
- performance budget
- accessibility full-flow gate
- analytics/event naming contract
- provider mock contract for auth/payment/capacity/notification
- migration and rollback rehearsal
- Case Study v5 narrative rewrite

## v5.0 — Connected Matchday Platform

**목표:** Matchday Companion을 실제 서비스 연동을 수용할 수 있는 제품 아키텍처로 전환합니다.

v5.0의 실제 외부 연동 범위는 v4.9에서 확정합니다. OAuth, member DB, payment, realtime capacity, notification, AI inference 중 실제로 연결한 항목만 Production 기능으로 표기합니다. 연결하지 않은 provider는 simulation/mock 상태를 유지하고 Case Study와 제품 UI에서 그 경계를 명시합니다.

### v5.0 acceptance

- Find → Decide → Join → Play → Return 전체 상태 계약 일관성
- recommendation / participation / matchday / return domain separation
- exact Production HTTP + Chromium verification
- responsive + accessibility + recovery gate
- current main / product baseline / exact Production / Render durable facts sync
- portfolio narrative와 실제 구현 범위 일치
