## Status

FootMate is no longer treated as frozen for current development. The 2026-09-12 close-out remains a historical QA snapshot only. v1.1 resumes iteration from the verified baseline without rewriting the approved source HTML files.

## Goal

Raise the prototype from a functionally verified portfolio demo to a more coherent product experience by improving visual hierarchy, interaction consistency, responsive behavior, and the alignment between the Live Demo and Case Study.

## Design principles

1. Preserve verified product logic and state transitions.
2. Keep `demo-source.html` and `index-source.html` as baseline source artifacts during the first refinement pass.
3. Consolidate visual tokens instead of adding screen-specific color overrides.
4. Improve the core journey first: Home → Match Detail → Payment → Game Day / Result → Profile.
5. Keep user-facing recommendation explanation separate from PM/QA evidence density.
6. Treat accessibility and reduced-motion behavior as design constraints, not post-processing.

## Technical review

The current shell/runtime architecture is intentionally preserved in this first pass to isolate visual changes from product logic. However, v1.1 confirms a structural limitation: `demo-source.html` remains a large single HTML source and runtime behavior is spread across patch/finalize/hardening layers that override globals and mutate DOM state.

A later architecture pass should consider:

- CSS token/component consolidation into fewer layers
- ES module boundaries for matching, state, persistence, UI, and validation
- reducing global function overrides such as `window.goScreen`, `window.switchDay`, and related patches
- replacing shell-time `document.write()` composition with a direct static/module entry where practical
- preserving the existing regression and Production Smoke contracts while migrating incrementally
- refreshing third-party GitHub Actions major versions separately from the product/UI change set; the hosted runner currently warns that several action releases still target the deprecated Node 20 action runtime even though the project test runtime now uses Node 24

This structural work is not required to validate the first visual pass and should not be mixed into the same change set unless a visual/UX improvement cannot be implemented safely without it.
