# FootMate v5.1 — AI Match Assistant

## 목표

사용자가 경기 조건을 자연어로 말하면 AI가 이를 구조화된 검색 조건으로 해석하고, 기존 FootMate recommendation engine이 실제 샘플 경기의 후보·순위·추천 이유를 결정합니다.

AI가 기존 추천 로직을 대체하지 않습니다. v5.0의 recommendation / participation / matchday / return domain ownership, browser persistence, provider registry와 cross-domain consistency guardrail을 유지합니다.

현재 Real App IA에서는 **Home이 AI Match Assistant의 입력/실행 entry를 소유하고, Discover가 결과 탐색을 소유**합니다. Home의 example suggestion도 단순 copy가 아니라 실제 Assistant 실행을 거쳐 structured constraints를 만들고 Discover로 이동합니다. Discover는 full Assistant를 중복 mount하지 않고 현재 AI 조건을 compact summary/edit surface로만 이어받습니다.

## AI Agent Workflow

`Context → Plan → Tools → Guardrail → Observe`

- **Context** — 현재 지역·포지션·레벨 browser state와 사용자의 자연어 요청
- **Plan** — 요청에서 지역·포지션·레벨·최대 가격·최대 이동 시간·시작 시간 조건을 구조화
- **Tools** — Vercel AI Gateway, 기존 deterministic recommendation ranking, 현재 sample match catalog
- **Guardrail** — AI는 경기 ID·가격·잔여 자리·주소·순위를 생성하지 않으며, 허용된 enum/범위 밖의 output은 제거하거나 제한
- **Observe** — `connected-ai` / `rules-fallback`, 실제 사용 model, 마지막 검색 조건을 browser state와 응답에서 추적

## Runtime boundary

### Connected AI path

`/api/ai-match-assistant`는 server-side에서 Vercel AI Gateway Responses API를 호출합니다.

- primary model: `openai/gpt-5.4-mini` (`FOOTMATE_AI_MODEL`로 override 가능)
- provider fallback model: `openai/gpt-5.4-nano` (`FOOTMATE_AI_FALLBACK_MODEL`로 override 가능)
- auth: `AI_GATEWAY_API_KEY` 우선, Vercel Production에서는 deployment OIDC를 `getVercelOidcToken()`으로 request-time 해석
- primary output: strict JSON Schema structured output
- primary/fallback output: strict JSON Schema structured output + 동일 server-side allowlist/range validation
- input length / payload size 제한
- same-origin check
- lightweight request rate limit
- no-store response

AI output은 검색 조건만 반환합니다. 실제 경기 결과는 client의 기존 recommendation ranking에 다시 통과시킵니다.

### Real App IA / handoff

- **Home** — AI Match Assistant prompt, 실행 가능한 example suggestion, loading/pressed/fallback 상태와 짧은 For You personalization을 소유
- **Discover** — Home에서 생성된 AI query/structured constraints를 이어받아 결과 수·조건 summary/edit·filter/sort·zero-result recovery·전체 목록을 소유
- **Detail** — 사용자가 고른 match의 decision information과 이후 참가 흐름을 소유
- **Join / MY** — joined-match status와 profile/settings 역할을 유지하며 Assistant/result UI를 중복 소유하지 않음
- **Handoff** — Home example 또는 submit → AI/rules 해석 → AI state 저장 → Discover 결과 state로 이동
- **Dedup** — Home For You는 1–2개 compact match만 노출하고 동일 경기의 별도 중복 추천 section을 만들지 않음

### Fallback path

AI Gateway의 primary model/provider가 `model_not_found`, `no_providers_available`, `access_denied`로 거절되거나 429/5xx를 반환하면 server-side에서 fallback model로 한 번 재시도합니다. 이 재시도가 성공하면 `connected-ai` 상태를 유지하되 응답에 실제 사용 model과 `fallbackUsed`를 남깁니다.

AI Gateway 자체가 구성되지 않았거나 primary와 provider fallback이 모두 실패하거나 AI output 검증에 실패하면 UI는 `rules-fallback`으로 전환합니다. 이 마지막 fallback은 지역·포지션·레벨·가격·거리·시간의 제한된 로컬 규칙 해석만 수행하며 AI로 표시하지 않습니다. 기존 경기 탐색·상세·참가 흐름은 계속 사용할 수 있습니다.

## HITL

AI는 참가 또는 결제를 자동 실행하지 않습니다.

- AI가 할 수 있는 것: 자연어 조건 해석, 조건 기반 경기 후보 표시
- 사용자가 직접 해야 하는 것: 경기 상세 확인, 참가 의사 결정, 로그인, 결제 확인

`join`과 `payment`는 명시적인 HITL 경계입니다.

## Data quality / safety

- **Completeness** — primary AI output field를 strict schema로 요구하고 fallback output도 동일 필드 계약으로 정규화
- **Validity** — region / position / level allowlist와 숫자 범위 검증
- **Freshness** — 경기 사실은 AI 지식이 아니라 현재 runtime sample records만 사용
- **Consistency** — 결과 순위는 기존 recommendation engine이 소유
- **Traceability** — 응답과 `window.__FOOTMATE_AI__`에서 version, workflow, ranking ownership, 실행 mode를 확인 가능

## State

- platform session: canonical `footmate:session`; legacy `footmate:v4:session` promotion/reconciliation은 storage infrastructure가 compatibility 용도로 처리
- discovery state: canonical `footmate:discovery`; filter/sort/result-list persistence는 discovery/platform repository가 소유
- AI assistant state: `footmate:v5.1:ai`

AI assistant state는 마지막 자연어 요청, 구조화된 조건, 실행 mode를 저장하고 Home → Discover handoff에서 재사용합니다. 외부 회원 DB나 cross-device sync는 추가하지 않습니다. `src/v5/ai-match-assistant.js`가 AI state와 handoff를 소유하며 `src/v4/discovery.js`는 AI state를 직접 소유하거나 legacy key를 직접 읽지 않습니다.

## Acceptance

- natural language → structured constraints
- Home example suggestion이 실제 Assistant 실행 후 Discover 결과로 이동
- Home submit → Discover handoff에서 query/constraints/result context 유지
- Discover에서 full Assistant 중복 mount 없음; compact condition summary/edit만 제공
- Home For You와 별도 duplicate matching section 간 동일 경기 중복 없음
- selected match identity가 Discover → Detail → Join 흐름에서 일관됨
- connected AI response와 rules fallback 모두 동작
- primary provider 거절 시 AI provider fallback 동작
- AI output이 실제 경기 record/ranking source of truth가 되지 않음
- no-result recovery 제공
- join/payment HITL 유지
- 320 / 375 / 390 / 430px responsive
- persistent bottom navigation과 content overlap 없음
- AI UI axe serious/critical 0
- 기존 v4.9 compatibility 및 v5 journey consistency 회귀 없음
- exact Production에서 `/api/ai-match-assistant` health와 실제 inference, app/Case Study release gate 확인

## Production claim policy

현재 v5.1 Production에서는 exact Vercel deployment와 실제 AI inference가 검증되었으므로 **AI Match Assistant의 connected AI path를 구현·검증된 Production 기능으로 표현할 수 있습니다.**

단, AI가 경기 사실·순위를 생성하는 것은 아닙니다. match catalog와 recommendation ranking의 Source of Truth는 현재 sample records + deterministic recommendation engine이며, auth/payment/capacity/notification은 deterministic mock boundary를 유지합니다.
