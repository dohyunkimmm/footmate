# 축구·풋살 개인 → 경기 매칭 · 2026-10-24

첫 방문 조건 선택 → AI 추천 카드 → 참가 시 로그인 → 직접 확정. 재방문은 저장한 조건의 추천 홈으로 연결한다. WIPPY에서 참고한 것은 추천 대상을 살펴보고 선택하는 흐름이며, 첫 조건 선택을 없애는 변경이 아니다.

## 첫 설정과 추천

- 1단계: 축구·풋살, 활동 지역을 선택한다.
- 2단계: 실력·포지션·선호 시간을 선택한다.
- 긴 설명·소개 메뉴 없이 선택을 끝내고 추천 카드로 이동한다. 이후 조건 변경은 홈에서 열고, 종목은 짧은 필터로 바꾼다.
- AI는 조건에 맞는 후보 최대 12개 안에서 순서를 정한다. 없는 ID·중복 ID를 제거하고 조건을 임의 완화하지 않는다. 사실·자리·추천 이유는 카탈로그로 확인한다.
- AI 실패 시 선택 조건의 기본 결과를 유지한다. 이전 요청이 늦게 돌아와 새 선택을 덮어쓰지 않도록 취소·요청 순서를 보호한다.

## 데모와 실제 Beta

- 공개 /demo는 예시 축구·풋살 경기 8개를 사용한다. 카드의 ‘데모 경기’ 표시를 유지하고 날짜를 미래 일정으로 갱신한다.
- 기존 카카오·구글·이메일 인증을 유지한다. 소셜 인증은 기존 /beta 콜백을 거쳐 선택한 데모 경기로 복귀한다.
- 데모 참가·취소는 로그인 사용자별 브라우저 기록이다. 실제 경기·참가 테이블, 대기·알림·이메일 발송을 생성하지 않는다.
- /beta는 실제 서버 경기·자리와 참가·취소·체크인·피드백을 사용한다. 과거 취소된 QA 경기만 있는 상태를 예시 경기로 오인시키거나 임의의 실모집 경기로 되살리지 않는다.
- 이전 /prototype은 과거 로컬 프로토타입과 자연어 해석·정정·조건 완화 검증 기록으로 보존한다.

## 유지 기준

앱은 최대 560px·한 열, Case Study는 1920px PC 읽기 환경을 우선한다. 로그인만으로 자동 참가하지 않으며 선택 경기·포지션을 유지한다. 브라우저의 선택·추천·데모 기록을 실제 서버 동기화나 모델 학습으로 표현하지 않는다.

QA는 첫 설정·실제 AI 응답·추천·인증 복귀·데모 참가/취소·서버 쓰기 방지·실제 Beta 회귀·반응형·접근성으로 구분한다. 기존 교육생 6명·28문장 검증과 매칭 만족도·전환 성과를 혼동하지 않는다.
