# Case Study · 포트폴리오 P0–P2 개선 · 2026-10-10

목적: 이력서를 별도로 제출하는 프로젝트 포트폴리오. 채용 연락, 이력서 CTA, 직무 랜딩은 포함하지 않음. 기존 9단계 목차와 색상·딥링크·이미지 확대·샘플 앱 경계를 유지.

## P0 · 판단과 구현/검증 근거의 연결

06 Design Decisions의 Guest First / Reasons First / Preserve & Recover를 각각 **문제 가설 → 선택과 Trade-off → 구현 경계 → 검증의 수준**으로 명시. 비회원 탐색이 실제 이탈을 줄였다는 결론, 추천이 시간·전환을 개선했다는 정량 결과, 복구가 실제 참가 성공률을 올렸다는 주장 금지. 과업 기반 사용자 검증 6명·8회와 개발 QA의 인과 관계는 입증하지 않음. 앱 캡처는 현재 UX 전체의 동결 스냅샷이 아닌 구현 기록이며 현재 /demo에서 직접 확인하도록 안내. /app은 브라우저 샘플·실제 PG 없음; /beta는 무료 Supabase 참가 연동.

## P1 · 여정/참가 분기/증거 수준

03의 여정 5단계 아래 설계 분기점 3개를 표시. 05의 6단계 정상 흐름은 보존하고 인증 상태·인증 취소·참가 실패의 각 결정 게이트를 구별. 07은 사용자 과업 수행, 개발 QA, 지표 정의의 세 근거 상태를 시각 구분하고 기존 원본 문서와 연결. 기존 수치·유효 관찰·모집단의 한계를 유지.

## P2 · 기존 내비게이션 향상

모바일에서 9단계 가로 목차를 sticky 및 scroll snap으로 강화하고, 선택 상태/포커스 표시를 보완. 의사결정 근거, 여정 분기, 검증 상태는 작은 화면에서 1열로 재배치. 확대 이미지/직접 링크/키보드 이동을 중복 구현하지 않음. 320·390·1440·1920px E2E 증거 구조/가로 넘침 체크 추가. 실제 사용자 200% 브라우저 확대에 대한 수동 승인과 실제 Beta KPI 측정은 여전히 후속 작업.

## QA 및 운영 잔여

Case Study 9단계 및 typography/axe/visual regression을 CI에서 유지. Production Smoke의 사전 버그로 확인된 Beta HTML 참조 버전은 실제 v=512와 일치시킴. 실제 Production READY와 HTTP·AI·브라우저 Smoke는 main 병합 후 SHA가 일치할 때만 완료로 선언.
