기준: GitHub `main`의 승인된 `demo.html` / `demo-source.html` 원본을 유지하고, 실제 브라우저·접근성·Production 배포를 반복 검증할 수 있는 자동 QA 레이어를 운영합니다. P0–P2 Product Hardening은 별도 runtime 계층에서 운영 상태·추천 설명·이벤트/KPI 관측·포트폴리오 전달력을 확장합니다.

## 검증 레이어

### 1. Node 회귀 테스트 · 36개

```sh
node --test tests/*.test.cjs
```

- `tests/regression.test.cjs` 20개 — Deep Link, 화면 이력, 퀴즈·타이머, 지역·결제·참가 상태, ELO, IME·키보드 등

- `tests/quality-hardening.test.cjs` 7개 — shell/승인 원본 동기화, Production metadata, core/product runtime 문법·loader, 저잔액 무부작용, ID 기반 persistence/migration

`tests/e2e/footmate.spec.cjs`를 Playwright Chromium에서 실행합니다.

- 실제 보이는 컨트롤을 통한 온보딩 완료
- 소개 화면 종료 후 Deep Link 복원
- `s-pay-low` 화면 이동 무부작용, 명시적 저잔액 시뮬레이션과 reload persistence
- 대표 화면 `s-splash` · `s-home` · `s-detail` · `s-pay` · `s-profile`의 axe WCAG 2 A/AA `serious`/`critical` 위반 0건 gate

## P0–P2 Product Hardening 검증 범위

세부 설계는 [PRODUCT-HARDENING-2026-09-11.md](PRODUCT-HARDENING-2026-09-11.md)에 기록했습니다.

- **P0 운영 현실성** — Payment·Participation·Match 상태 머신, 결제 실패/재시도, 중복 신청 차단, 참가 취소/환불, 노쇼, 대기→빈자리 제안→수락, 경기 취소

## 자동 접근성 검사에서 발견·수정한 실제 결함

axe gate를 적용하면서 테스트 자체가 아니라 UI에 존재하던 색 대비 문제를 확인했습니다. 승인 원본 HTML은 수정하지 않고 runtime 보정 레이어에서 최소 수정했습니다.

- 네이버 로그인 버튼: 녹색 배경 위 흰색 텍스트 대비 부족 → 어두운 텍스트로 보정
- 홈 화면 회색·파랑·초록 보조 텍스트/칩: WCAG AA 경계 미달 → 동일 색상 계열의 더 진한 runtime token으로 보정
- 팀 상세 포지션 다이어그램: 채워진/빈 포지션 텍스트 대비 부족 → field green과 filled text를 더 진한 녹색으로 보정
- 문서 동기화 후 `main` 재검증: 홈 초록 상태 chip 2개가 4.43:1로 재현 → axe 기준 4.5:1을 유지한 채 runtime 색 추가 보정
- Product Hardening PR #10 첫 실행: 새 PM 패널 보조 텍스트 4종이 2.97–4.29:1로 재현 → axe 기준이나 검사 범위를 낮추지 않고 `footmate-product-hardening.css` 텍스트 색을 더 진하게 보정해 동일 dialog gate 재통과

검사 기준을 낮추거나 위반을 예외 처리하지 않고 실제 표시 색을 보정했습니다.
