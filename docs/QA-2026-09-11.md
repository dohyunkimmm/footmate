# FootMate 검증 가능한 완성도 · 2026-09-11

기준: GitHub `main`의 승인된 `demo.html` / `demo-source.html` 원본을 유지하고, 실제 브라우저·접근성·Production 배포를 반복 검증할 수 있는 자동 QA 레이어를 추가합니다.

## 검증 레이어

### 1. Node 회귀 테스트 · 36개

```sh
node --test tests/*.test.cjs
```

- `tests/regression.test.cjs` 20개 — Deep Link, 화면 이력, 퀴즈·타이머, 지역·결제·참가 상태, ELO, IME·키보드 등
- `tests/runtime-patch.test.cjs` 9개 — 하드 필터, 추천 정렬, Data Quality, 이벤트 순서, 상태 연결 키, 홈 필터, 크레딧 등
- `tests/quality-hardening.test.cjs` 7개 — shell/승인 원본 동기화, Production metadata, 런타임 문법, 저잔액 무부작용, ID 기반 persistence/migration

### 2. Chromium 실브라우저 E2E · 5개

`tests/e2e/footmate.spec.cjs`를 Playwright Chromium에서 실행합니다.

- Production-like `/demo` shell과 전체 39개 화면·런타임 레이어 부팅
- 실제 보이는 컨트롤을 통한 온보딩 완료
- 소개 화면 종료 후 Deep Link 복원
- `s-pay-low` 화면 이동 무부작용, 명시적 저잔액 시뮬레이션과 reload persistence
- 대표 화면 `s-splash` · `s-home` · `s-detail` · `s-pay` · `s-profile`의 axe WCAG 2 A/AA `serious`/`critical` 위반 0건 gate

브라우저 테스트는 `pageerror`, same-origin HTTP 4xx/5xx, 의미 있는 `console.error`도 실패로 처리합니다.

### 3. Production Smoke · `main` push

`Regression 36`과 `Browser E2E + axe`가 먼저 성공한 뒤, 해당 `GITHUB_SHA`의 Vercel commit status가 `success`가 될 때까지 확인합니다. 이후 실제 `https://footmate-black.vercel.app`을 대상으로 검증합니다.

- HTTP: `/`, `/demo`, `/demo-source`, `footmate-core.js`, `footmate-finalize.js`
- Production `/`의 description·canonical·Open Graph·Twitter Card marker
- Production `/demo`의 shell loader와 전체 39개 화면
- 실제 Chromium에서 Case Study와 Demo 렌더링·런타임 부팅·홈 화면 이동
- same-origin HTTP 오류·브라우저 `pageerror`·의미 있는 `console.error` 없음

Production HTTP 결과는 `test-results/production-smoke.json`으로 기록합니다.

### 4. 실패 증거 Artifact

브라우저·Production QA는 성공/실패와 관계없이 GitHub Actions Artifact를 남깁니다.

- Playwright HTML report
- 실패 screenshot
- 실패 trace
- error context
- Production smoke JSON

Artifact 보존 기간은 14일입니다.

## 자동 접근성 검사에서 발견·수정한 실제 결함

새 axe gate를 처음 적용하면서 테스트 자체가 아니라 UI에 존재하던 색 대비 문제를 확인했습니다. 승인 원본 HTML은 수정하지 않고 `footmate-finalize.css` 런타임 보정 레이어에서만 최소 수정했습니다.

- 네이버 로그인 버튼: 녹색 배경 위 흰색 텍스트 대비 부족 → 어두운 텍스트로 보정
- 홈 화면의 회색·파랑·초록 보조 텍스트/칩: WCAG AA 경계 미달 → 동일 색상 계열의 더 진한 runtime token으로 보정
- 팀 상세 포지션 다이어그램: 채워진/빈 포지션 텍스트 대비 부족 → field green과 filled text를 더 진한 녹색으로 보정

검사 기준을 낮추거나 위반을 예외 처리하지 않고 실제 표시 색을 보정했습니다.

## PR 검증 상태

PR #3의 브라우저 QA에서 다음을 확인했습니다.

- 기존 Node 회귀 36개 성공
- Chromium E2E 5개 성공
- 대표 화면 axe WCAG 2 A/AA `serious`/`critical` 위반 0건
- 브라우저 QA Artifact 생성 성공

`Production Smoke`는 PR에서 의도적으로 실행하지 않고 `main` push에서만 실행합니다. 따라서 Production 직접 HTTP/실브라우저 자동 검증 완료 여부는 merge 후 `main` workflow 결과로 확정합니다.

## 사용자 수동 QA

사용자 확인 기준으로 다음 수동 QA에서 문제 없음을 확인한 상태를 유지합니다.

- 실제 iPhone·Android 핵심 흐름
- VoiceOver / TalkBack 실제 발화·포커스·동적 상태 알림
- 전체 39개 화면 Console Error 전수 확인

자동 axe 검사는 대표 화면의 기계 검증이며 위 수동 스크린리더 QA를 대체한다고 표현하지 않습니다.

## 남은 범위

- 실제 로그인·위치·결제·DB·알림·외부 AI 모델·운영자 시스템 연동
- 실데이터 기반 정원·경기 상태 Freshness 및 서버 기준 상태 충돌 차단
- GitHub `main` Required Check 강제 설정: 현재 연결된 GitHub 통합에서 ruleset/branch-protection 쓰기 기능이 제공되지 않아 CI 정의와 실행은 가능하지만 저장소 보호 규칙 자체는 이 세션에서 설정하지 못함

`main` merge 후 Production Smoke까지 성공한 경우, 프로토타입 범위의 자동 검증 체계는 Node 로직 회귀 + 실제 Chromium E2E + 대표 화면 접근성 gate + 실제 Production smoke + 실패 증거 Artifact로 구성됩니다.
